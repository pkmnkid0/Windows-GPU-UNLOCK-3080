# RTX 3080 10GB notes

**English** | [한국어](RTX3080-10GB.ko.md) | [New machine](NEW-MACHINE.en.md) | [Compatibility](COMPATIBILITY.en.md)

> **Status.** This tree adds source-level admission for the RTX 3080 10GB to the
> generated LOCAL workflow. It does not add a named 3080 profile, and no
> maintainer has run a 3080 build from this tree. The first write build on your
> card is your machine's own experimental test.

## Admitted configuration

The admission is deliberately exact. A nearby RTX 3080 variant is not covered.

| Item | Required value |
|---|---|
| PCI device ID | `10de:2206` or `10de:2216` |
| Chip revision | `0xb72000a1` (GA102, revision bits not masked) |
| VRAM | exactly `0x2800` MiB (10 GiB) |
| Class/revision | `030000a1` |
| nvgop | an exact reviewed `.text` hash; the recorded 3080 build is `6000a` |
| Console | a recognized non-aggregate console, or a recognized AMI aggregate console with an EDID driver |
| Platform | AMI/UEFI firmware with the captured segment, bus, root port and display paths |
| Capture state | power-on state, `MEM1`/`BME0`, no bus mastering, two agreeing cold captures |

The following are **not** admitted by this change:

- 12GB RTX 3080 or RTX 3080 Ti variants, including any `0x3000` MiB capture;
- an RTX 3080 ID with another chip revision;
- a 3090 / 3090 Ti memory size on a 3080, or `0x2800` on a 3090 / 3090 Ti;
- a card whose captured subsystem, PROM, driver hashes, root port or display
  paths are outside the reviewed LOCAL model.

## Evidence and what it does not prove

| Record | What it reports | Limit |
|---|---|---|
| [Project-origin MSI 3080 report](https://github.com/rough2515-hub/rtx3080-unlock-public/blob/a08254d269af30ace9e57237abd3d8e6c261e8f5/evidence/unlock-boot-09/REPORT.TXT) | One successful transaction on an MSI RTX 3080 10GB: `220610de` / `1462:3890`, chip `b72000a1`, `0x2800` MiB, nvgop `6000a`, SS0 `0x88888888`, SS1 `0x8`, FLR and clean containment | Different code version and machine; not this tree and not your card |
| [Upstream PR #72](https://github.com/impacifist/Windows-GPU-UNLOCK/pull/72) | One cold boot on a Maxsun B760M / RTX 3080 LHR: `221610de` / `7377:2000`, chip `b72000a1`, `0x2800` MiB, nvgop `6000a`, and the `.text` hash now in `proven.json` | Its fixed `b760m-3080lhr` profile and B760M aggregate-console allowances are not in this tree; the rebased wrapper still needs a new hardware run per that PR |
| [Issue #20](https://github.com/impacifist/Windows-GPU-UNLOCK/issues/20) | Read-only diagnostic capture of an ASUS RTX 3080 FE: `220610de`, `0x2800` MiB, nvgop `60009` | Diagnostics only; no unlock or successful transaction |

The `6000a` entry was added to `research/profile/proven.json` because that exact
driver code was released cleanly on hardware in PR #72. The existing `60008`,
`60009` and `60010` GA102 entries come from other machines and are not RTX 3080
success records. A 3080 capture that reports one of those builds is still checked
against the exact reviewed hash, but no 3080 run has validated that combination
in this tree.

PR #72 also adds a fixed B760M profile and `GU_TOPO_B760M` aggregate-console
allowances. This fork does not import them. The generic LOCAL generator must
recognize your complete ownership graph on its own; a board that needs different
aggregate rules is refused rather than patched around.

## Current B660M / Zotac candidate

The values below are Windows inventory values from the machine used to prepare
this fork. They are **not** probe captures. A BIOS, VBIOS, driver or card change
invalidates them.

| Field | Inventory value |
|---|---|
| GPU | NVIDIA GeForce RTX 3080 10GB |
| PCI device | `10de:2206` |
| Subsystem | `19da:1612` |
| Chip revision | `0xb72000a1` |
| VRAM | `0x2800` MiB (10240 MiB) |
| VBIOS | `94.02.42.40.3b` |
| Driver | 617.42 |
| Motherboard / BIOS | MSI MAG B660M BAZOOKA DDR4 (MS-7D43) / `H.H0` |
| CPU | Intel Core i5-12400F (no iGPU) |

The two captures must agree with each other. If `DIAGnn.TXT` shows a different
device ID, chip revision or memory size, stop. Do not edit the envelope or the
generated header to make the capture fit.

**No iGPU warning.** This CPU has no integrated graphics. If the first write run
leaves the RTX without display output, there is no motherboard video fallback.
Prepare a second display adapter for recovery, or perform the first run on a
machine with a known recovery path. Do not rely on blind recovery.

## Build a local profile

This is the workflow in [NEW-MACHINE.en.md](NEW-MACHINE.en.md), not a fixed
profile build. Needs LLVM (`clang`, `lld-link`), MSVC build tools, Python 3.10+,
the five firmware assets and a FAT32 USB stick.

### 1. Capture twice

From an administrator PowerShell in the repository root:

```powershell
# Windows ESP GUID: Get-Partition | Where-Object IsSystem | Select Guid
.\research\profile\new-machine.ps1 -Drive D -WindowsEspGuid 'YOUR-WINDOWS-ESP-GUID' -Assets 'C:\LOCAL-FIRMWARE\assets'
```

The first run builds the read-only generic probe and copies it to the stick as
`EFI\BOOT\BOOTX64.EFI`. Shut down fully, select the stick in the firmware boot
menu, and let it start Windows. Repeat the full shutdown and boot once more.

The probe writes `DIAGnn.TXT`, `PROM.BIN` and `IMGnn.BIN`. Check that both
captures report:

- one NVIDIA display controller at the captured segment/bus;
- device `2206` or `2216`, chip `b72000a1`, memory `0x2800`;
- class/revision `030000a1`;
- the same root/display paths and console ownership;
- an nvgop version and `.text` hash inside `proven.json` (the recorded 3080
  build is `6000a`).

The probe only reads. It cannot compile with unlock code.

### 2. Generate the profile

Run the same command again. It copies the two captures into
`research/profile/local/capture/`, builds `fwsec-locate`, and runs
`research/profile/make-profile.py`. On success it writes
`internal-boot/unlock/profile-local.h`, `research/profile/local/profile.json` and
the test fixtures. On failure it stops with the reason.

Check `profile.json` before continuing:

- `Board` is `220610de` or `221610de`;
- `Chip` is `b72000a1`;
- `Memory` is `2800`;
- `ClassRevision` is `030000a1`;
- the PCI segment, bus, root port and display paths match both captures;
- `Aggregate`, `ChildCount`, `NoEdidDriver` and the nvgop code match the
  captures.

A refusal is a result. Do not add an unknown nvgop hash, remove a check or copy
another machine's constants.

### 3. Run the host evidence

```powershell
.\research\profile\test-profile.ps1
```

This compiles the generated profile and runs the complete host job set: refusal
cases on your captures, configuration and ownership checks, the console replay,
the cold pre-check, and the production transaction against your PROM and stock
assets with EFI/MMIO/DMA simulated. Every job must pass; only then is
`research/profile/local/test-results.json` written. An aggregate console adds
its own required replay. A partial pass is not evidence.

### 4. Build and stage the USB package

```powershell
.\research\headless\build-usb.ps1 -HardwareProfile local
```

Then read [HEADLESS-USB.en.md](HEADLESS-USB.en.md) and rerun with `-StageUnlock`.
Staging is refused if the header, fixtures, PROM hash or source tree no longer
match the test evidence.

### 5. First supervised boot

The first boot of the staged stick is the first time anything writes to the GPU.
Choose it manually after a full shutdown, with a keyboard connected and a
recovery plan ready. It is never automatic.

## If the generator refuses

| Refusal | Action |
|---|---|
| nvgop hash not released cleanly | Keep the full capture; do not add a hash without hardware evidence |
| memory is `3000` or another size | The card is not the admitted 10GB tuple; stop |
| chip revision differs | The capture is outside the reviewed GA102 revision; stop |
| aggregate ownership is not recognized | Keep the capture and report the graph; do not port PR #72's B760M allowances blindly |
| missing EDID driver on an aggregate console | The current aggregate model requires an EDID driver; do not remove the check |
| capture disagreement | Capture two more complete cold boots; do not average or edit records |

## Recovery and limits

Read [HEADLESS-USB.en.md](HEADLESS-USB.en.md) before staging. Preserve the
Windows ESP and recovery partition; keep BitLocker protection off and the volume
fully decrypted. The tools do not create, delete or format partitions.

A failed transaction can leave the card without display output. With no iGPU,
prepare another display adapter or another machine before the first run. A cold
power cycle, CMOS clear or vendor reflash may not restore a card whose firmware
state was interrupted.

The recorded evidence covers one transaction per machine at most. It does not
establish repeated automatic cold boots, sleep/hibernate resume, long-term
stability, games, compute workloads or another RTX 3080. A matching ID and chip
revision are admission conditions, not proof that your card will complete the
transaction.

## Reporting

After a supervised run, open a compatibility report with the `profile.json`
values, the boot log and before/after benchmark results. Never publish the PROM,
firmware assets or partition-specific EFI binaries. See
[CONTRIBUTING.en.md](CONTRIBUTING.en.md). A reviewed profile can then move your
constants into `machine-profile.h`; `proven.json` widens only with that evidence.

notices when redistributing source or USB packages.
