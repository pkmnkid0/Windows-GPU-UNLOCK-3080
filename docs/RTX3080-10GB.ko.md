# RTX 3080 10GB 안내

[English](RTX3080-10GB.en.md) | **한국어** | [새 장비](NEW-MACHINE.en.md) | [호환성](COMPATIBILITY.ko.md)

> **상태.** 이 소스트리는 RTX 3080 10GB를 자동 LOCAL 경로에 소스 수준으로
> 허용합니다. 고정 3080 프로필을 추가한 것이 아니며, 유지관리자가 이
> 소스트리로 3080을 실행한 기록도 없습니다. 카드에서의 첫 쓰기 빌드는
> 해당 장비의 실험적 시험입니다.

## 허용하는 구성

허용 범위는 의도적으로 정확합니다. 비슷한 다른 3080 변형은 포함하지 않습니다.

| 항목 | 필요한 값 |
|---|---|
| PCI device ID | `10de:2206` 또는 `10de:2216` |
| 칩 revision | `0xb72000a1` (GA102, revision 비트를 마스킹하지 않음) |
| VRAM | 정확히 `0x2800` MiB (10 GiB) |
| Class/revision | `030000a1` |
| nvgop | 검증된 정확한 `.text` 해시. 기록된 3080 빌드는 `6000a` |
| 콘솔 | 인식된 non-aggregate 콘솔, 또는 EDID 드라이버가 있는 인식된 AMI aggregate 콘솔 |
| 플랫폼 | 캡처한 segment·bus·root port·화면 경로를 가진 AMI/UEFI 펌웨어 |
| 캡처 상태 | power-on 상태, `MEM1`/`BME0`, bus mastering 없음, 일치하는 cold 캡처 2개 |

이 변경으로 허용하지 **않는** 구성:

- 12GB RTX 3080, RTX 3080 Ti, `0x3000` MiB 캡처;
- 다른 칩 revision의 RTX 3080 ID;
- 3080에 3090·3090 Ti의 메모리 크기, 또는 3090·3090 Ti에 `0x2800`;
- 캡처한 subsystem·PROM·드라이버 해시·root port·화면 경로가 검증된 LOCAL
  모델 밖인 카드.

## 근거와 한계

| 기록 | 보고 내용 | 한계 |
|---|---|---|
| [프로젝트 기원 MSI 3080 보고](https://github.com/rough2515-hub/rtx3080-unlock-public/blob/a08254d269af30ace9e57237abd3d8e6c261e8f5/evidence/unlock-boot-09/REPORT.TXT) | MSI RTX 3080 10GB에서 트랜잭션 1회 성공: `220610de` / `1462:3890`, chip `b72000a1`, `0x2800` MiB, nvgop `6000a`, SS0 `0x88888888`, SS1 `0x8`, FLR·clean containment | 다른 코드 버전과 장비. 이 소스트리나 사용자의 카드 시험이 아님 |
| [상위 PR #72](https://github.com/impacifist/Windows-GPU-UNLOCK/pull/72) | Maxsun B760M / RTX 3080 LHR에서 cold boot 1회: `221610de` / `7377:2000`, chip `b72000a1`, `0x2800` MiB, nvgop `6000a`, 그리고 `proven.json`에 추가한 `.text` 해시 | 고정 `b760m-3080lhr` 프로필과 B760M aggregate-console 예외는 이 소스트리에 없음. PR 설명에 따르면 rebase된 wrapper는 새 실기기 시험이 필요 |
| [이슈 #20](https://github.com/impacifist/Windows-GPU-UNLOCK/issues/20) | ASUS RTX 3080 FE의 읽기 전용 진단 캡처: `220610de`, `0x2800` MiB, nvgop `60009` | 진단 자료뿐. 언락이나 성공 트랜잭션 근거가 아님 |

`6000a` 항목은 PR #72에서 해당 드라이버 코드가 실기기에서 깨끗하게 해제된
근거로 `research/profile/proven.json`에 추가했습니다. 기존 GA102의 `60008`,
`60009`, `60010` 항목은 다른 장비에서 온 것이며 RTX 3080 성공 기록이 아닙니다.
3080 캡처가 그 빌드를 보고해도 정확한 검증 해시와 비교하지만, 이 소스트리에서
3080으로 그 조합을 시험한 기록은 없습니다.

PR #72의 고정 B760M 프로필과 `GU_TOPO_B760M` aggregate-console 예외는 이
포크에 포함하지 않았습니다. 일반 LOCAL 생성기가 사용자의 전체 소유권 그래프를
스스로 인식해야 하며, 다른 aggregate 규칙이 필요한 보드는 예외를 덧붙이지 않고
거부합니다.

## 현재 B660M / Zotac 후보

아래 값은 이 포크를 준비한 장비의 Windows 인벤토리 값입니다. **프로브 캡처가
아닙니다.** BIOS·VBIOS·드라이버·카드가 바뀌면 무효입니다.

| 항목 | 인벤토리 값 |
|---|---|
| GPU | NVIDIA GeForce RTX 3080 10GB |
| PCI device | `10de:2206` |
| Subsystem | `19da:1612` |
| 칩 revision | `0xb72000a1` |
| VRAM | `0x2800` MiB (10240 MiB) |
| VBIOS | `94.02.42.40.3b` |
| 드라이버 | 617.42 |
| 메인보드 / BIOS | MSI MAG B660M BAZOOKA DDR4 (MS-7D43) / `H.H0` |
| CPU | Intel Core i5-12400F (iGPU 없음) |

두 캡처가 서로 일치해야 합니다. `DIAGnn.TXT`가 다른 device ID·칩 revision·
메모리 크기를 보이면 중단하세요. 캡처에 맞추기 위해 envelope나 생성 헤더를
직접 고치지 마세요.

**iGPU 없음 경고.** 이 CPU에는 내장 그래픽이 없습니다. 첫 쓰기 실행 후 RTX
화면이 돌아오지 않으면 메인보드 화면으로 대체할 수 없습니다. 복구용 두 번째
디스플레이 어댑터를 준비하거나, 복구 경로가 확인된 다른 장비에서 첫 실행을
하세요. 눈으로 확인할 수 없는 복구를 전제로 하지 마세요.

## 로컬 프로필 만들기

고정 프로필 빌드가 아니라 [NEW-MACHINE.en.md](NEW-MACHINE.en.md)의 절차입니다.
LLVM(`clang`, `lld-link`), MSVC 빌드 도구, Python 3.10+, 펌웨어 asset 5개,
FAT32 USB가 필요합니다.

### 1. 캡처 2회

저장소 루트의 관리자 PowerShell에서 실행합니다.

```powershell
# Windows ESP GUID: Get-Partition | Where-Object IsSystem | Select Guid
.\research\profile\new-machine.ps1 -Drive D -WindowsEspGuid 'YOUR-WINDOWS-ESP-GUID' -Assets 'C:\LOCAL-FIRMWARE\assets'
```

첫 실행은 읽기 전용 generic 프로브를 빌드해 USB의 `EFI\BOOT\BOOTX64.EFI`로
복사합니다. 완전히 종료한 뒤 펌웨어 부팅 메뉴에서 USB를 선택해 Windows를
시작하고, 같은 과정을 한 번 더 반복하세요.

프로브는 `DIAGnn.TXT`, `PROM.BIN`, `IMGnn.BIN`을 기록합니다. 두 캡처 모두
다음을 보고해야 합니다.

- 캡처한 segment/bus에서 NVIDIA 디스플레이 컨트롤러 하나;
- device `2206` 또는 `2216`, chip `b72000a1`, memory `0x2800`;
- class/revision `030000a1`;
- 동일한 root·화면 경로와 콘솔 소유권;
- `proven.json` 안의 nvgop 버전과 `.text` 해시(기록된 3080 빌드는 `6000a`).

프로브는 읽기만 하며 언락 코드와 함께 컴파일할 수 없습니다.

### 2. 프로필 생성

같은 명령을 다시 실행합니다. 두 캡처를 `research/profile/local/capture/`로
복사하고 `fwsec-locate`를 빌드한 뒤 `research/profile/make-profile.py`를
실행합니다. 성공하면 `internal-boot/unlock/profile-local.h`,
`research/profile/local/profile.json`, 시험 fixture를 기록하고, 실패하면
이유와 함께 중단합니다.

계속하기 전에 `profile.json`을 확인하세요.

- `Board`가 `220610de` 또는 `221610de`;
- `Chip`이 `b72000a1`;
- `Memory`가 `2800`;
- `ClassRevision`이 `030000a1`;
- PCI segment·bus·root port·화면 경로가 두 캡처와 일치;
- `Aggregate`, `ChildCount`, `NoEdidDriver`, nvgop 코드가 캡처와 일치.

거부는 결과입니다. 알 수 없는 nvgop 해시를 추가하거나 검사를 지우거나 다른
장비의 상수를 복사하지 마세요.

### 3. Host 증거 실행

```powershell
.\research\profile\test-profile.ps1
```

생성된 프로필을 컴파일하고 전체 host 작업을 실행합니다. 캡처에 대한 거부
사례, 구성·소유권 검사, 콘솔 재현, cold 사전검사, 실제 PROM과 stock asset을
사용하는 production 트랜잭션(EFI/MMIO/DMA 시뮬레이션)이 포함됩니다. 모든
작업이 통과해야 `research/profile/local/test-results.json`이 기록됩니다.
Aggregate 콘솔은 별도의 재현 작업을 추가합니다. 일부만 통과한 결과는 증거가
아닙니다.

### 4. USB 패키지 빌드·staging

```powershell
.\research\headless\build-usb.ps1 -HardwareProfile local
```

[HEADLESS-USB.en.md](HEADLESS-USB.en.md)를 읽은 뒤 `-StageUnlock`으로 다시
실행하세요. 헤더·fixture·PROM 해시·소스트리가 시험 증거와 달라지면 staging이
거부됩니다.

### 5. 첫 감독 부팅

Staging된 USB의 첫 부팅이 GPU에 처음 쓰는 순간입니다. 완전 종료 후 키보드를
연결하고 복구 계획을 준비한 상태에서 직접 선택하세요. 자동 부팅은 없습니다.

## 생성기가 거부할 때

| 거부 | 대응 |
|---|---|
| nvgop 해시가 깨끗하게 해제된 적 없음 | 전체 캡처를 보존하세요. 실기기 근거 없이 해시를 추가하지 마세요 |
| 메모리가 `3000` 등 다른 크기 | 허용된 10GB 조합이 아닙니다. 중단하세요 |
| 칩 revision 불일치 | 검증된 GA102 revision 밖입니다. 중단하세요 |
| aggregate 소유권을 인식하지 못함 | 캡처와 그래프를 보존해 보고하세요. PR #72의 B760M 예외를 그대로 이식하지 마세요 |
| aggregate 콘솔에 EDID 드라이버 없음 | 현재 aggregate 모델은 EDID 드라이버를 요구합니다. 검사를 제거하지 마세요 |
| 캡처 불일치 | 완전한 cold 부팅 캡처를 2개 더 수집하세요. 평균을 내거나 기록을 고치지 마세요 |

## 복구와 한계

Staging 전에 [HEADLESS-USB.en.md](HEADLESS-USB.en.md)를 읽으세요. Windows ESP와
복구 파티션을 보존하고 BitLocker 보호를 끈 상태로 완전히 복호화해 두세요.
도구는 파티션을 생성·삭제·포맷하지 않습니다.

실패한 트랜잭션은 카드에 화면 출력이 없는 상태를 남길 수 있습니다. iGPU가
없으므로 첫 실행 전에 다른 디스플레이 어댑터나 다른 장비를 준비하세요. 콜드
전원 재순환, CMOS 초기화, 벤더 재플래시로도 펌웨어 상태가 중단된 카드가
복구되지 않을 수 있습니다.

기록된 근거는 장비당 많아야 트랜잭션 1회입니다. 반복 자동 cold boot,
절전/최대 절전 복귀, 장기 안정성, 게임, 연산 워크로드, 다른 RTX 3080을
입증하지 않습니다. ID와 칩 revision이 맞는 것은 허용 조건일 뿐, 사용자의
카드가 트랜잭션을 완료한다는 증거가 아닙니다.
